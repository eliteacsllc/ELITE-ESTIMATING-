# Elite Capability Symmetry & Need-to-Know Presentation

Essential capabilities MUST exist locally or behind replaceable provider interfaces. Cross-repo integrations may enhance quality, scale, intelligence, economics, convenience, or resilience but MUST NOT be required for fundamental operation.

Customer-facing surfaces expose only estimate inputs, evidence, source/provenance, confidence where useful, review/approval status, totals, revisions, and decisions appropriate to the role. Internal agents, model/provider routing, hidden evaluation, chain-of-thought, infrastructure topology, secret metadata, internal provider costs/margins, stack traces, and debug internals remain internal by default.

Every essential capability requires a local/core path or replaceable adapter, bounded failure behavior, safe degradation, stable public contracts, separate internal audit detail, and presentation filtering.

Preferred resolution: `local capability -> optional Elite accelerator -> alternate approved provider -> safe degraded mode`.

Test optional data/provider outage, local estimate-kernel continuity, fallback behavior, role serialization, customer redaction, operator visibility, provenance preservation, and cross-tenant isolation.
